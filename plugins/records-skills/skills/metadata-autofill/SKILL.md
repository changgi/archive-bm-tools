# 메타데이터 후보 제안

1. `python "${CLAUDE_PLUGIN_ROOT}"/skills/metadata-autofill/scripts/extract_candidates.py 문서폴더/ --existing 목록.xlsx --key 파일명 -o 산출/메타데이터_후보.xlsx`
2. '불일치 — 확인'을 먼저 보고한다. 기존 목록 값이 틀렸을 수도, 본문 읽기가 틀렸을 수도 있다.
3. 후보가 여러 개면 서식 줄(제목·시행·발신명의)에서 나온 것을 우선하되, 고른 이유를 적는다.
4. 값을 정해 목록에 넣을 때는 '근거' 열에 파일과 위치(예: 공문.pdf 1쪽 3줄)를 함께 적는다. 근거 없는 값은 넣지 않는다.
5. 기록관리시스템에 직접 등록하지 않는다. 정리한 목록은 records-qa-gate를 거쳐 사람에게 넘긴다.
6. 비밀 표시가 있는 문서는 열지 않는다(하네스가 막는다).

## 등록부 필수 요소 점검 (NAK 8:2022 부속서 C·D)
`python "${CLAUDE_PLUGIN_ROOT}"/skills/metadata-autofill/scripts/nak8_check.py 등록부.csv -o 산출/메타데이터점검.xlsx [--before 이전_등록부.csv]`
- 필수 요소(생산자유형·기관명·기록계층·기본식별자·제목·전자기록물여부·기록유형·용량·단위·분류체계유형·분류명·생산일시·종료일시·보존기간·보존장소·공개구분)가 비었는지.
- 세트 요소(시스템식별자↔유형, 기타제목↔유형, 기술내용↔기술유형, 비치사유↔비치기간, 무결성체크값↔체크법 등), 비공개·부분공개면 비공개사유, 부속서 D 생산자유형(기안자·결재자 등)이면 개인명, 종료일시 ≥ 생산일시, 전자기록물이면 포맷명.
- `--before`: 등록 후 바꿀 수 없는 요소(생산자·제목·생산일시, 5.1)가 바뀌었는지 기본식별자로 대조.
- 비밀(17.1) 열은 값을 읽지 않는다.

근거: NAK 8:2022(v2.3) 기록관리 메타데이터 표준 — 자동 입력이 안 되는 요소는 기록전문가가 직접 입력해야 하는 부담이 있다. 이 스킬은 그 입력을 '근거 달린 후보'로 줄인다.
