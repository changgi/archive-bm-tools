# 행정정보 데이터세트 관리기준표 초안

## 0. 관리대상 선정(A·B·C) — 관리기준표보다 먼저
`python "${CLAUDE_PLUGIN_ROOT}"/skills/dataset-schedule/scripts/dataset_screen.py 시스템목록.xlsx --org 기관명 -o 산출/데이터세트_관리대상_선정.xlsx`
- 기관 정보시스템 목록(시스템명·개요·데이터세트 내용·DB 저장·연계 표출·자체 생성·다른 법률)으로 「2026년 기록물관리 지침」 유형 구분에 따라 A(관리대상)·B①~④(데이터세트 미대상)·C(별도 기록관리 방안: 업무관리·RMS·대표 홈페이지) 후보를 달고, 지침의 '데이터세트 관리대상 선정 협의 서식' 칸 순서로 채운다.
- B·C의 '선정 제외 사유'(노란 칸)는 구체적으로 고쳐 쓴다(지침: 반드시 작성). 대표 홈페이지라도 게시판 등 업무 데이터가 기록관리체계에서 빠지면 A 후보로 둔다.
- 유형 확정은 기록관 검토 → 관할 영구기록물관리기관 협의. 국가기록원 관할은 행정정보 데이터세트 종합관리시스템(www.darm.go.kr, 업무망)으로 하고, 중앙행정기관은 반드시 쓴다. 확정 후 바꾸면 사유를 공문 등으로 이력관리.
- A로 정해진 시스템만 아래 관리기준표 초안을 만든다.

## 1. 관리기준표

1. 시스템 담당자에게 테이블 정의서(또는 information_schema 내보내기)를 받아 csv로 만든다: 테이블명, 테이블설명, 컬럼명, 컬럼설명, 자료형.
2. `python "${CLAUDE_PLUGIN_ROOT}"/skills/dataset-schedule/scripts/dataset_schedule.py 스키마.csv --org 기관명 --system 시스템명 --dbms "Oracle 19c" [--answers 답변.json] -o 산출/데이터세트_관리기준표.xlsx`
3. 노란 칸(필수인데 비어 있음)을 작성 주체별로 묶어 질문 목록을 만든다: 시스템담당자(DBMS·구축년도·연계), 업무담당자(법령·업무내용·대상), 기록관담당자(보존기간·책정사유·정보공개·처분).
4. 기산일 후보는 날짜 컬럼 이름으로 고른 것이다. "업무가 끝나는 시점"이 맞는지 담당자가 확정한다.
5. 보존기간은 task-suggest로 후보를 보고, 관할 영구기록물관리기관과 협의해 정한다(시행령 제26조①2·제34조의3).

- 유형 판단 규칙은 국가기록원 '행정정보 데이터세트 관리대상 유형 구분 서식'의 선정협의 예시(시스템 21개, 검토의견 포함)와 맞춰 보았다(21개 모두 같은 판단, 2026-11-20). 기술 시스템·단순 중계 여부는 시스템명·개요로만 본다(데이터 칸의 '사업모니터링' 같은 말로 B 판정하지 않음). 사내포털(EIP)·전자문서시스템은 C, 홈페이지·모바일 앱은 C(게시판 이름을 단 시스템은 A 검토).

근거 서식: 국가기록원 누리집 업무안내·자료 > 기록관리 자료실 > 행정정보 데이터세트 > '관리기준표 서식(한글) 및 작성방법'. 표준: NAK 35:2020(v1.0) 행정정보 데이터세트 기록관리 기준. 시행령 제25조⑥(관리기관·법령·시스템·데이터·업무·기록관리 정보).
## 1-2. 평가·폐기 준비 (실행매뉴얼 2020 3.3·3.4)
`python "${CLAUDE_PLUGIN_ROOT}"/skills/dataset-schedule/scripts/dataset_disposal.py 단위기능.xlsx --system 시스템명 --today 2026-11-21 -o 산출/데이터세트_평가.xlsx`
- 열: 단위기능, 테이블, 기산일컬럼, 보존기간, 처분제약(년), 연도별건수('2018:100;2019:200').
- 처분제약 보류기간과 보존기간이 모두 지난 기산연도를 계산해 '평가 상정 목록'과 영역별 '평가심의서'(범위·건수, 운영부서·영향도·전문요원·심의회 칸)를 만든다. 준영구·영구는 대상 아님.
- '확인용 SQL'은 건수를 세는 SELECT만 쓰고 DELETE는 주석으로만 둔다 — 운영부서가 참조 무결성·첨부 경로·시스템 영향을 검증한 뒤 평가심의 결과를 근거로 실행(국가기록원 삭제지원 도구 사용 가능). 이 도구는 DB에 접속하지 않는다.
- 삭제 뒤 '폐기 결과 기록부'에 단위기능·범위·폐기량·방식·일시·근거를 남긴다. 별도 스토리지·백업 매체도 각각 파기.
- 관리대상 선정·관리기준표·평가심의 없이 운영부서가 임의로 지우면(백업 후 삭제 포함) 기록물 무단 폐기에 해당할 수 있다.

## 2. SIARD 이관 파일 구조 점검 (NAK 35 부속서 B, SIARD 2.1)
`python "${CLAUDE_PLUGIN_ROOT}"/skills/dataset-schedule/scripts/siard_check.py 데이터세트.siard -o 산출/SIARD점검.csv`
- ZIP(비압축·deflate만, 암호화 금지, .siard), 최상위 content/·header/만, header/siardversion/2.1/ 빈 폴더, header/metadata.xml·metadata.xsd.
- content 폴더·파일 이름 규칙(영문자로 시작, 영문·숫자·_), 테이블 폴더의 tableN.xml·xsd, metadata.xml 스키마·테이블 폴더와 content가 같은지, 열 수가 xsd와 같은지.
- 테이블 값은 열지 않는다. SIARD는 NAK 37:2025 데이터베이스형 '수용가능포맷'(보존포맷은 CSV·JSON·XML)이고 스키마(구조정보)를 함께 보존하도록 권장된다.

## 3. 재현정보 함께 챙기기 (국가기록원 2025 연구 「오픈 포맷을 활용한 행정정보 데이터세트 보존 방안」 3.6)
데이터세트는 원시 데이터만으로 테이블 관계·제약조건·화면 표시를 되살리기 어렵다. 이관·보존 준비 때 다음을 시스템 담당자에게 받아 함께 둔다.
- 스키마(DDL·테이블정의서·ERD), 코드표(공통코드 값↔의미), 화면 재현용 서식(XSLT·CSS 등), 재현 도구 이름·버전·설치본·매뉴얼, 추가 처리용 SQL 스크립트.
- 연구가 제안한 오픈 포맷은 metadata.xml의 `<table>` 안 `<representationInfo method=…><description/><location/>`로 representation/ 폴더의 도구를 가리키고,
  장기보존패키지(NEO3)에는 RepresentationInformation/ 폴더를 둔다. 아직 표준(NAK 31-2·35) 확정 전 제안이므로, SIARD 파일 안에 representation/ 폴더를 넣지 않는다(P_4.2-1: content/·header/ 밖 금지) — 패키지 쪽에 따로 둔다.

이관·삭제는 국가기록원 SIARD_KR 지원도구(같은 게시판 '지원도구 설치 파일 및 매뉴얼')를 쓰며, 이 스킬은 실행하지 않는다.
