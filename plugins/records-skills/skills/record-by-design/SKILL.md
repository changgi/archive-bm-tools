# 생산 시점 기록화 — 맥락·증거성을 갖춘 기록 패키지

현용 단계에서 만드는 파일이 나중에도 "누가, 무슨 업무로, 왜, 무엇과 이어져" 만들었는지 스스로 말하고, 원본이 그대로라는 것을 증명하며,
같은 메타데이터에서 여러 매개로 바뀌어 쓰이도록 한다. 국가기록원 기록관리시스템 등록을 대신하지 않고, 등록에 넣을 값을 미리 갖춘 상자를 만든다.

## 1. 만들기
```
python "${CLAUDE_PLUGIN_ROOT}"/skills/record-by-design/scripts/capture.py capture 원본파일 --task "단위과제명" --agency 기관 --dept 부서 \
    --person 담당자 --role 기안자 --period 10년 --access 공개 \
    --activity "이 기록을 만든 업무 행위" --purpose "왜 만들었나" --summary "한두 줄 요약" \
    --relation "참조:선행기록식별자" --id 2026-기획-0001 -o 산출/기록패키지
```
- 부분공개·비공개는 `--reason`(정보공개법 제9조제1항 몇 호와 구체 사유)이 없으면 멈춘다.
- 제목·생산일시를 주지 않으면 metadata-autofill의 후보로 채우고 `점검.md`에 '후보'로 적는다(담당자 확인).
- 비밀 표시가 보이면 만들지 않는다. 개인정보 후보가 있으면 공개 매개에 본문 요약을 싣지 않는다.

## 2. 패키지 안
| 파일 | 하는 일 | 근거 |
|---|---|---|
| `data/원본/` | 원본 그대로(복사 후 해시 일치 확인) | 시행령 제4조 진본성·무결성 |
| `metadata.json` | NAK 8 요소 번호·이름(1 생산자·3.1·4.1·8.1·9.1·11·12·13.1·15.1·16·17.3·23 무결성·22 관계)+업무활동·생산목적 | NAK 8:2022 필수 상위 요소 |
| `context.jsonld` | 기록–생산자–단위과제–업무활동–관련 기록을 RiC-O로 | ICA RiC-O 1.0 |
| `events.jsonl` | 생산·등록·다이제스트·파생·고정성 점검 사건(덧붙이기만) | PREMIS 3.0 사건, NAK 8 21 이력 |
| `매개/` | 등록대장.csv · 공개데이터.json · 요약.html · 카드.txt | 하나의 메타데이터에서 여러 매개 |
| `bagit.txt`·`bag-info.txt`·`manifest-sha256.txt`·`tagmanifest-sha256.txt` | 옮겨도 스스로 설명·검증되는 상자 | BagIt RFC 8493 |

## 3. 지속하기
- `capture.py verify <패키지>`: 원본·태그 해시를 다시 계산해 '고정성 점검' 사건을 쌓는다. 원본이 바뀌었으면 실패로 남기고 해시 목록은 고치지 않는다.
- `capture.py derive <패키지>`: 메타데이터를 고친 뒤 매개를 다시 만든다(원본은 그대로).
- `capture.py batch 목록.xlsx|csv [--task --agency --dept --period]`: 목록 한 행 = 파일 하나(열: 파일·제목·생산일자·식별자·관계·요약·공개구분·공개제한사유 …, 파일 경로는 목록 폴더 기준). 빈 칸은 옵션 기본값으로 채우고, 비밀은 거부·비공개 사유 누락은 입력 오류로 `일괄_결과.csv`에 남긴다.
- `capture.py catalog <패키지 폴더> [--verify]`: 패키지 전체에서 `기록목록.csv`(관계·고정성 포함), `공개데이터.jsonl`(공개·개인정보 후보 없음만), `연결그래프.jsonld`(RiC-O @graph), `목록.html`(검색·관계 링크, 모바일 카드형)을 만든다. 각 매개는 metadata.json 하나에서 다시 만들 수 있어 원본을 건드리지 않고 퍼뜨릴 수 있다.
- 주기 점검은 fixity-check(폴더 전체 기준선), 보존 포맷 사본은 preservation-convert, 이관 전 점검은 records-qa-gate와 함께 쓴다.

## 하지 않는 것
기록관리시스템 등록·이관, 공개 게시, 원본 수정, 비밀기록물 처리.
