## 읽기 전에 — 공통 규칙 5가지

1. **입력은 시스템에서 내보낸 엑셀(.xlsx)이 기본입니다.** 열 이름이 조금 달라도 대부분 알아봅니다(예: `생산부서`, `생산부서(처리과)명`, `처리과명`). 못 알아보면 아래 「[열 이름이 안 맞을 때](#열-이름이-안-맞을-때)」를 보세요.
2. **결과는 언제나 새 파일**로 `산출/` 아래에 생깁니다. 원본은 읽기만 합니다.
3. **결과는 '후보'와 '초안'입니다.** 폐기·이관·공개 결정과 제출은 담당자가 합니다.
4. **비밀기록물은 Claude가 열지 않습니다.** 비밀 관련 계산은 [classified-records-check](#26-classified-records-check--비밀기록물-점검서식-1011)처럼 담당자가 비밀 전용 장비에서 직접 돌립니다.
5. **끝나면 검수**: 결과물마다 [records-qa-gate](#3-records-qa-gate--내보내기-전-품질-관문)가 한 번 더 확인합니다.

### 스킬을 직접 부르는 법
보통은 말만 하면 되지만, 꼭 특정 스킬을 쓰게 하려면 `/records-skills:스킬이름`을 입력합니다.

```text
/records-skills:retention-review 입력/기록물목록.xlsx 보존기간 검토해줘
```

### 직접 실행(선택)
「직접 실행」 명령은 터미널에서 Claude 없이 돌리는 방법입니다. 저장소를 내려받은 폴더의 `plugins/records-skills`에서 실행합니다. Claude에게 맡길 때는 몰라도 됩니다.

# 📝 생산·등록

## 1. production-status-report — 생산현황 통보(서식 1~11)

> 🧾 **비유:** 연말정산 도우미. 영수증(등록정보)을 넣으면 항목별로 더하고, 빠진 영수증과 잘못 적은 칸을 먼저 알려 줍니다.

**이럴 때** 매년 전년도 생산분을 국가기록원에 통보할 때. 정리 기간에 등록정보를 미리 점검할 때.

**준비할 것** — `입력/` 폴더 하나에 파일 이름에 아래 낱말이 들어가게 넣습니다(.xlsx).

| 파일 이름에 든 낱말 | 필수 | 채우는 서식 |
|---|---|---|
| `등록정보` | ✅ | 서식 1·2 — 생산현황, 목록 |
| `시청각` | | 서식 3·4 |
| `회의목록` / `회의체` | | 서식 8 / 서식 9 |
| `회의록` (폴더) | | 회의록 구성요소 점검 |
| `시청각원본` (폴더) | | 시청각 쪽수 = 파일 수 확인 |
| `행정박물` | | 서식 5·6 |
| `간행물` | | 서식 7 |
| `통보서식` | | 국가기록원이 올해 배포한 원본 서식(없으면 킷의 서식 사용) |

`비밀`이 들어간 파일은 **이름도 적지 않고 건너뜁니다.** 서식 10·11은 [26번](#26-classified-records-check--비밀기록물-점검서식-1011)으로 따로 만듭니다.

**이렇게 말하세요**
```text
입력 폴더로 2025년 생산분 생산현황 통보서 만들어줘.
등록정보만 먼저 점검해줘. 통보 기한은 2026-05-31이야.
열 이름이 안 맞으면 고쳐서 돌려줘.
```

**받는 결과** (`산출/통보준비_2025/`)
- `통보전_확인.md` — **먼저 여는 파일.** 단계별 결과, 고칠 것 상위 항목, 비운 서식, 제출 전 사람이 할 일
- `생산현황_2025.xlsx` — `요약` · `부서×보존기간` · `고칠 것` 시트
- `생산현황_통보서식_2025.xlsx` — 국가기록원 통보서식에 값을 채운 것
- `시청각_점검.xlsx`, `회의록_점검.xlsx`, `행정박물_점검.xlsx`, `간행물_점검.xlsx` — 넣은 파일이 있을 때

**찾아내는 '고칠 것'** 등록번호 누락·중복, 보존기간 비표준(예: '7년'), 단위과제·공개구분 누락, 비전자 쪽수 불일치, 생산시스템구분 코드(01~06) 오류, 회의록 구성요소 누락, 지정회의 속기록 부족 등

**직접 실행**
```bash
python skills/production-status-report/scripts/run_all.py 입력 --year 2025 -o 산출/통보준비_2025
# 열 이름이 조금 다를 때: --fix-headers
```

**알아 둘 점**
- 산출 폴더가 비어 있지 않으면 **덮어쓰지 않고 멈춥니다.** 다시 돌릴 때는 새 폴더 이름을 주세요.
- 통보서식의 총계·소계 수식은 엑셀에서 열어 값을 확인하세요. 서식 변경·시트 삭제는 하지 않습니다.
- 지자체·교육청·기타공공기관은 서식 2 제출 대상이 아닐 수 있습니다. 기관 유형을 확인하세요.

## 2. records-register-audit — 정리 기간 등록정보·실물 대조

> 📦 **비유:** 택배 송장과 실제 상자를 하나하나 맞춰 보는 검수원.

**이럴 때** 매년 정리 기간에 시행규칙 제14조 확인 사항을 점검할 때.

**준비할 것** ① 시스템 등록정보 목록 ② 실물 점검표(상자·쪽수를 직접 센 것). 두 파일을 잇는 열은 `철분류번호` 또는 `등록번호`.

**이렇게 말하세요**
```text
등록정보.xlsx랑 실물점검표.xlsx 대조해서 정리 점검해줘.
```

**받는 결과** `요약` · `점검 결과` 시트 — 미등록 실물, 실물 없음, 쪽수 불일치, 공개구분·접근권한·비밀 표시의 적절성, 등록번호 표기, 한 상자에 생산연도·보존기간·단위과제가 섞인 것, 🆕 철당 100매 초과(시행규칙 제9조③), 🆕 등록정보 수정 이력에 수정일자·내용·사유가 다 있는지(제6조·제8조②)

**직접 실행** `python skills/records-register-audit/scripts/register_audit.py 등록정보.xlsx 실물점검표.xlsx --key 등록번호 -o 산출/정리점검.xlsx`

## 3. records-qa-gate — 내보내기 전 품질 관문

> ✈️ **비유:** 비행기 이륙 전 체크리스트. 다른 스킬이 만든 결과물도 나가기 전에 여기를 한 번 더 통과합니다.

**이럴 때** 목록·메타데이터·이관 패키지를 내보내기 직전. 다른 스킬이 끝난 뒤 자동으로.

**하는 일 두 가지**
1. **검수** — 기록의 4대 속성(진본성·무결성·신뢰성·이용가능성)으로 필수 항목 빈칸, 원본과의 차이, 패키지 매니페스트·해시를 확인 → `검수결과.md`
2. **열 이름 맞춤(header_check)** — 기관 시스템에서 내보낸 파일의 **머리글만** 읽어 각 스킬이 어떤 열을 알아보는지 알려 줍니다. 자료 행은 읽지 않습니다.

| 판정 | 뜻 |
|---|---|
| 맞음 | 그대로 알아봄 |
| 비슷함 | 띄어쓰기·괄호·별표·'년도/연도' 차이 — `--fix`로 머리글만 고친 사본을 만듦 |
| 후보 | 두 열 이상이 겹쳐 하나를 골라야 함 — `--map`으로 직접 짝지음 |
| 없음 | 그 열이 없음 — 받아들이는 이름 예시를 보여 줌 |

**이렇게 말하세요**
```text
이 결과물 내보내도 되는지 검수해줘.
우리 시스템 내보내기 파일 열 이름 맞는지 봐줘.
```

**직접 실행**
```bash
python skills/records-qa-gate/scripts/header_check.py 입력/등록정보.xlsx
python skills/records-qa-gate/scripts/header_check.py 입력/등록정보.xlsx --map "부서=생산부서" --fix -o 산출/등록정보_열맞춤.xlsx
```

## 4. metadata-autofill — 메타데이터 빈칸 채우기

> 🔍 **비유:** 서류 더미를 읽고 표지에 붙일 포스트잇을 써 주는 조수. 단, "몇 쪽 몇째 줄에서 봤다"는 근거를 함께 붙입니다.

**이럴 때** 목록의 제목·생산기관·생산일자·문서번호·수신자 빈칸을 채울 때. 목록과 본문이 다른 곳을 찾을 때.

**준비할 것** 본문 파일 폴더(txt·docx·hwpx·pdf). 기존 목록이 있으면 함께.

**이렇게 말하세요**
```text
스캔문서 폴더 본문에서 제목이랑 생산일자 후보 뽑아서 기존목록.xlsx 빈칸 채울 후보 만들어줘.
```

**받는 결과** `후보` 시트 — 항목별 후보값, **근거 위치**, 기존 값과의 불일치 표시

**직접 실행** `python skills/metadata-autofill/scripts/extract_candidates.py 본문폴더 --existing 기존목록.xlsx --key 관리번호 -o 산출/메타데이터_후보.xlsx`

**알아 둘 점** 후보는 후보일 뿐입니다. 목록에 옮기기 전에 원문과 대조하세요.

---

- **NAK 8 필수 요소 점검**(`nak8_check.py`): 등록부의 필수·세트·해당시 필수(부속서 D 개인명), 종료일시≥생산일시, `--before`로 등록 후 변경 불가 요소(생산자·제목·생산일시) 대조. 비밀 열은 값을 읽지 않음.

## 5. docno-extract — 문서번호 추출·범위 펼치기

> 🔢 **비유:** "3~7번"이라고 적힌 쪽지를 3, 4, 5, 6, 7 다섯 장으로 나눠 주는 일.

**이럴 때** 목록 한 칸에 `기획행정담당관-351-92~94`처럼 범위로 적힌 문서번호를 낱개로 펼쳐야 할 때.

**이렇게 말하세요**
```text
목록.xlsx 문서번호 열에서 범위 다 펼쳐줘.
```

**받는 결과** `문서번호` 시트 — 원래 행 번호와 함께 낱개 문서번호 한 줄씩. `-92~94` → `-92`, `-93`, `-94`

**직접 실행** `python skills/docno-extract/scripts/extract_docno.py 목록.xlsx --col 문서번호 --id-col 관리번호 -o 산출/문서번호.xlsx`

**알아 둘 점** 터무니없이 큰 범위(오타 가능성)는 펼치지 않고 표시만 합니다. 기준은 `--max-range`로 바꿉니다.

## 6. task-suggest — 단위과제·보존기간 추천

> 🧭 **비유:** 도서관 사서가 책 제목을 보고 "이건 이 분류 같아요" 하고 후보 서가 세 곳을 알려 주는 것.

**이럴 때** 단위과제가 비었거나 보존기간을 무엇으로 할지 모를 때.

**준비할 것** 제목이 든 목록. 기관 유형(중앙행정기관·지방자치단체·공공기관·교육(행정)기관·학교·대학) 또는 기관 기준표.

**이렇게 말하세요**

## 40. official-doc-check — 공문서 표기 점검

> ✍️ **비유:** 교정지에 빨간 펜. 날짜·시간·금액 쓰는 법과 항목 번호, '끝' 표시를 규정대로 맞췄는지 봅니다.

**이럴 때** 기안문·보고서를 결재 올리기 전, 처리과 문서 품질 점검, 신규 직원 공문서 작성 교육 자료를 만들 때.

**이렇게 말하세요**
```text
이 기안문 공문서 표기 맞는지 봐줘. 금액 한글로 고쳐 쓸 값도 알려줘.
```

**알아 둘 점** 원본은 고치지 않습니다. 규정은 특별한 사유가 있으면 다른 방법도 허용하므로 제안으로 봅니다. 근거: 「행정업무의 운영 및 혁신에 관한 규정」 제7조, 같은 규정 시행규칙 제2조·제4조.
