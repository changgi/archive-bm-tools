## 7. 생산 시점 기록화부터 확산까지

**넣은 것** `단위과제.xlsx`(지역축제운영·물품계약), `업무폴더/`(과제 이름 하위 폴더에 업무 파일 하나씩)

**흐름**
1. `appraisal_worksheet.py`가 업무과정 분석 작업지(`1_업무분석.xlsx`)와 `기록화설정.json` 초안을 만듭니다. 물품계약은 부분공개(제7호)로 고쳐 업무 폴더에 둡니다.
2. `capture.py sweep`이 두 파일을 기록 패키지로 만듭니다(`2_기록패키지/` — 원본, NAK 8 메타데이터, RiC-O 연결, 사건 이력, BagIt 해시).
3. 계획 파일을 고친 뒤 `sweep`을 다시 돌리면 **바뀐 파일만** 새 패키지가 되고, 이전 패키지와 '개정' 관계로 이어집니다. 같은 파일은 두 번 만들지 않습니다.
4. `catalog --verify`가 내부용 목록(`3_내부목록/` — 3건, 고정성 통과)을, `catalog --public-only --base-url …`이 게시용 묶음(`4_게시용/`)을 만듭니다.

**결과에서 볼 것**
- `4_게시용/목록.html`에는 공개 2건만 있습니다. 부분공개인 계약은 빠졌습니다.
- `oai_dc.xml`의 `dc:relation`에 `개정:urn:records:…`가 있어, 고친 계획이 처음 계획과 이어져 있습니다.
- `맥락지도.html`은 가상시 → 문화과 → 지역축제운영 → 기록으로, 이 기록이 어디서 나왔는지 보여 줍니다.
- 같은 메타데이터 하나에서 `공개데이터.jsonl`·`연결그래프.jsonld`·`feed.atom`·`sitemap.xml`·`기록목록.csv-metadata.json`(CSVW)이 함께 나옵니다.
